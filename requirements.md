# Requirements

## Overview
The system shall provide a simple task‑management application that exposes a FastAPI JSON API for CRUD operations, a server‑rendered HTML UI styled with Tailwind CSS, and a Django admin interface for data management. The same PostgreSQL (or compatible) database is shared between FastAPI and Django.

## Functional Requirements (EARS)
### API Layer (FastAPI)
* **When** a client sends `GET /api/tasks`
* **Then** the system **shall** return `200 OK` with a JSON array of all tasks, each containing `id`, `title`, `description?`, `completed`, and `due_date?`.

* **When** a client sends `POST /api/tasks` with a valid payload `{title, description?, due_date?}`
* **Then** the system **shall** create the task, respond with `201 Created` and the created task including its generated `id`.

* **When** a client sends `GET /api/tasks/{id}` for an existing task
* **Then** the system **shall** return `200 OK` with the task data; for a non‑existent `id` it **shall** return `404 Not Found`.

* **When** a client sends `PUT /api/tasks/{id}` with a full update payload
* **Then** the system **shall** update the task fields, respond `200 OK` with the updated representation; for unknown `id` respond `404`.

* **When** a client sends `DELETE /api/tasks/{id}` for an existing task
* **Then** the system **shall** remove the task and respond `204 No Content`; for unknown `id` respond `404`.

### UI Layer (FastAPI + Jinja2 + Tailwind)
* **When** a user navigates to `/`
* **Then** the system **shall** display a responsive task list page styled with Tailwind, showing each task’s title, completion status, and due date.
* **When** the user clicks the "Add Task" button
* **Then** the system **shall** present a Tailwind‑styled form for creating a new task.
* **When** the user submits a valid form
* **Then** the system **shall** call the FastAPI `POST /api/tasks` endpoint, show the new task in the list, and display a success toast.
* **When** the user clicks an "Edit" link on a task row
* **Then** the system **shall** present a pre‑filled form; submitting updates the task via `PUT /api/tasks/{id}` and refreshes the list.
* **When** the user clicks a "Delete" button
* **Then** the system **shall** confirm the action, call `DELETE /api/tasks/{id}`, and remove the row from the UI.

### Admin Interface (Django)
* **When** a developer accesses `/admin/`
* **Then** Django shall present the standard admin login page.
* **When** an authenticated admin navigates to the `Task` model admin page
* **Then** they **shall** be able to create, edit, delete tasks using Django’s built‑in UI, and all changes shall be reflected in the FastAPI API and UI.

## Non‑Functional Requirements
* The application shall use Python 3.11+.
* The Tailwind compilation shall be performed via `fastapi‑tailwind` (no Node.js required).
* The API shall return JSON conforming to OpenAPI 3.1 schema generated by FastAPI.
* The codebase shall include unit tests covering ≥ 80 % of the API logic.
* The project shall be containerised with Docker, exposing ports 8000 (FastAPI) and 8001 (optional Django static files if needed).
* All source files shall be type‑checked with `mypy` and linted with `ruff`.

## Acceptance Summary
* All API endpoints behave as described and return correct status codes.
* The HTML UI is fully functional, responsive, and styled with Tailwind.
* Django admin can manage tasks and changes are instantly visible via the API/UI.
* CI pipeline passes lint, type‑check, tests, and Docker build.
